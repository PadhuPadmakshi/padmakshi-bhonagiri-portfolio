Front-end and UI/UX work — shown, not just described

The DOM DoIT job description asks for a portfolio that shows UI work, not only backend code. This page is that evidence, from the author's Iowa-tailored resume. No Figma files are published — that Figma work came from client UX teams — but the translation of a design specification into a working, accessible interface is shown here.

Case studies

Centene — Member Self-Service Portal Modernization

Figma → responsive semantic HTML5/Sass/JavaScript. Enterprise design system + Storybook, Bootstrap screens migrated to design-system components, axe-core in Azure DevOps. Fixes in claims filters, date pickers, modal dialogs, and multi-step forms, checked with JAWS, NVDA, and axe.

Frontiers — Author and Reviewer Submission Platform

Shared component library with documented states, accessibility notes, and do/don't guidance. Multi-step submission with progress steps, inline validation, and save-and-resume. WCAG fixes via axe/WAVE, checked with NVDA/JAWS.

New Jersey DOL — Unemployment Insurance Claimant Services

Mobile-friendly weekly certification, layout tables replaced with semantic markup, plain-language questions and errors, shared UI controls to state standards. Tested with JAWS, keyboard-only navigation, and axe before each release.
